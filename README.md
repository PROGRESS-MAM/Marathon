# Marathon 0.3 — Reporting und AQC-Abgleich

Voraussetzungen: Python >=3.11, TOOLBOX und Searcher (PROGRESS-MAM/ES-Search). Der Searcher-Dateimodus setzt Windows und Zugriff auf das SMB-Metadatenexport-Share voraus. Für AQC muss auch der konfigurierte UNC-Pfad erreichbar sein; bei fehlendem AQC-Zugriff werden Zustand und Bericht nicht geschrieben.

res/cred.env.example nach res/cred.env kopieren und SMB_HOST sowie bei Bedarf SMB_USER und SMB_PASSWORD lokal eintragen. Niemals echte Zugangsdaten oder state/, log/ und reports/ einchecken. Alle Pfade und Suchfeldnamen stehen oben in marathon.py; das erweiterbare Kollektionsmapping liegt unter res/collections.json.

Ablauf: python marathon.py startet den dauerhaften Prozess. Befehl report erstellt einen manuellen Bericht, quit beendet. Automatischer Bericht ab 09:00 lokaler Zeit einmal täglich; Einmalläufe mit --manual bzw. --auto-once. Searcher-Sollmengen bestimmen Gesamt; Abweichungen erhalten eine Fehlerliste, fehlende Clips bleiben im Zustand.

Bei jedem Bericht scannt Marathon nur die direkten, nichtleeren Dateien unter target_path (AQC). Aus dem Namen (c)PROGRESS__10Mbit__Identifier__Titel[.Erweiterung] werden Identifier und Titel ermittelt und nur eindeutig einem aktiven DEFA-Clip zugeordnet. Dateien ohne Metadatenzuordnung bleiben im Ordner und werden in keiner Queue gezählt; der nächste Lauf versucht die Zuordnung erneut. Mehrdeutige Namen und mehrere AQC-Dateien zum selben Clip werden nicht neu zugeordnet und gemeldet. Bei ausbleibendem Wiedersehen einer früher zugeordneten Datei bleibt die Queue zur Prüfung erhalten und es entsteht eine Warnung. Die Dateipräsenz allein belegt nicht zweifelsfrei, dass ein externer Kopiervorgang abgeschlossen ist; eine Übergabe per atomarer Umbenennung/Abschlussmarker wäre künftig sicherer.

Eine zugeordnete AQC-Datei setzt queue=qc und status=waiting_qc, aber niemals ready=true. Der bestehende running_qc-Status bleibt bei Wiederholung erhalten. report_only=True erstellt keinerlei Auftragsdateien oder Dateiverschiebungen; False bricht weiterhin ab. Sichtbare Queues: Restore, Transcode, QC. Intern enthält jeder Clip transcode.phase (analysis/conversion/completed) und die Zeitfelder der beiden Phasen. Ohne künftige Worker-Rückmeldungen können Analyse- und Umrechnungsdauer noch nicht ermittelt werden. Eigene Transcodes sollen später über Clip_ID-Rückmeldungen zugeordnet werden; aktuell verwendet der AQC-Abgleich auch für sie den Dateinamen.

Der Zustand wird atomar unter state/marathon.json ersetzt. Nicht mehrere Instanzen parallel starten. Vorhandene Berichte mit der alten Spaltenreihenfolge bleiben für Deltas lesbar.
